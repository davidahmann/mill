## Approved outcomes

1. A durable run can produce a compact, versioned continuation packet that names
   its exact identity, current phase, evidence bindings, resource observations,
   and the next _attended_ safe action. It never performs that action.
2. Recovery routing is covered with exhaustive state cases and generated
   state/error combinations. An uncertain worker or external effect always
   routes to reconciliation before another mutation.
3. Mill carries a deterministic brownfield evaluation pack. It exercises the
   local lifecycle with representative repository conditions and explicitly
   distinguishes harness evidence from a claim that a model can solve every
   codebase.
4. Public status and continuation evidence report only provider-measured token
   fields, including cache-token observations when emitted. Cost remains
   unavailable unless a provider supplies an auditable settlement; no estimate
   or billing control is inferred.
5. Mill makes the present trusted-host builder boundary explicit and rejects an
   unqualified request to represent it as an isolated builder. A separately
   qualified adapter remains future work; this increment does not mount, expose,
   or proxy credentials into a sandbox.

## Future forms deliberately not implemented here

6. A bounded repository-context adapter could later import a revision-bound
   symbol index (for example SCIP) and preserve repository-owned summaries. It
   must be optional, deterministic, digest-bound, non-authoritative, and unable
   to execute code or become a graph service.
7. A governed improvement record could later capture an operator-owned,
   source-bound proposal from evaluation evidence. It may recommend a worker or
   harness change, but must not modify prompts, policies, models, or runtime
   routing without a new approved task, regression evaluation, and release
   qualification.

## Boundaries

- One writer, one disposable worktree, native checks, exact-candidate review,
  and separate attended release effects remain mandatory.
- No daemon, parallel writers, auto-merge, deployment, hosted service,
  arbitrary-stack support, hidden telemetry, Graphiti/graph database, or
  autonomous/self-modifying worker is introduced.
- No provider usage or cost is fabricated. Missing, partial, and stale evidence
  stays visible as such.
- New evaluation fixtures are deterministic and local. They are not a
  replacement for a customer repository qualification or human review.

## Acceptance evidence

- Native type, lint, formatting, workflow, schema, coverage, packed-package, and
  exact-candidate audit checks pass.
- Tests prove continuation routing cannot propose an unsafe mutation for each
  lifecycle state and selected generated recovery sequences.
- Documentation describes the present security boundary and the deferred forms
  above without overclaiming support.
- The committed candidate receives a read-only full-diff review before a draft
  pull request. CI, resulting-main evidence, release qualification, GitHub
  release, and npm readback remain separately recorded.

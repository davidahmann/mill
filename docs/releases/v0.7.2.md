# Mill v0.7.2

This correction makes the documented `run next` command pass explicit approval
and attendance through the CLI parser. Missing approvals still block execution;
an isolation request cannot silently select the trusted-host worker. The tests
exercise the public command parser as well as the underlying lifecycle.

The release flow waits longer for npm metadata after a successful publication. A
protected recovery workflow can finish a proven partial publication without
publishing the immutable package again. It keeps the original source and
workflow identities separate from the recovery controller, verifies registry
bytes and signatures, reruns the package canary, and retains final channel
readback. Existing GitHub releases require separate reconciliation.

Recovery captures job logs privately on old and new GitHub CLI versions. Raw
output is excluded from error messages and public receipts. Test-only Docker
state uses atomic writes so a polling reader cannot observe truncated JSON.

Version 0.7.1 remains immutable. This source record describes intended scope;
the protected workflow's `release-evidence-final.json` establishes publication.
Use the exact verified release when updating a downstream pin.

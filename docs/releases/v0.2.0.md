# Mill v0.2.0

This release extends attended delivery to source-backed follow-up task
compilation, bounded brownfield context, experimental native Node adoption and
separately approved merge plans. Draft-only remains the default. No builder or
reviewer receives forge mutation authority.

Review now binds the complete base-to-candidate diff. Native validation failures
have one bounded repair; producer-bound CI and resulting-main evidence remain
separate gates. Public subjects omit commit trailers/private email metadata,
status reports usage without invented costs, and audits explicitly report
structural assurance.

The release workflow retains one preserved tarball and adds the independently
pinned v0.1.5 verifier before protected OIDC publication and registry/GitHub
readback. The attached qualification and release evidence, not this source note,
establish publication and exact supported tuples.

After those gates pass, install this exact version with lifecycle scripts off:

```sh
npm install --save-dev --ignore-scripts @davidahmann/mill@0.2.0
npx --no-install millctl --version
```

Existing repositories must deliberately update their Mill version pin and
requalify. Legacy reviews without full-diff scope remain readable but cannot
certify a new delivery; obtain fresh review. Native Node ESM/npm adoption is
experimental, not arbitrary-stack or enterprise integration support. The real
JSON Server canary uses a disclosed local npm overlay of an upstream pnpm
repository; it does not qualify pnpm support.

See the planning, brownfield, approvals and release guides for exact boundaries
and recovery. Keep v0.1.5 artifacts as the trust root; never move released tags
or imply that an older binary can safely interpret newer approval state.

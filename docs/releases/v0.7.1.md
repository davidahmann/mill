# Mill v0.7.1

This maintenance candidate closes gaps where a valid document or a passing
command could imply more than the evidence established.

Every task admission route enforces an outcome's declared acceptance scope.
Human and external scenarios require exact attestations. Approved outcomes can
receive their first task, and closure promotes a successor only after validating
its task binding. Preservation-only work no longer requires invented new
behavior.

OCI operations retain ownership records before launch. Recovery removes only
containers whose identity and labels match those records. An uncertain launch
blocks retries and destructive state cleanup. A host controller's deadline is
not a daemon-independent kill guarantee after controller death.

Release reconstruction checks source, qualification, package and registry
identity together. Publication retries bounded registry reads, never the publish
effect. The workflow explicitly selects this release as GitHub Latest and
records fresh npm and GitHub channel observations in its final evidence.

The source record describes intended scope before publication. The protected
workflow's `release-evidence-final.json` is the provider closure. Existing
release and task records remain historical evidence. This release does not
expand the qualified stack or establish a downstream application's provider or
customer acceptance.

## Qualification scope

The live-worker sequence and support tuple are retained together from the
[v0.2.1 qualification asset](https://github.com/davidahmann/mill/releases/download/v0.2.1/qualification.json).
They describe the 2026-09-05 observation with Codex CLI 0.153.1, Node 24.20.0
and npm 11.19.0, expiring on 2026-10-05 at 09:11:04.564 UTC. Their canonical
digests are
`sha256:f2cc3e536f48d45ae11d7066ca2e0d56a3aa80292f66f8401c16c9f10abea2e1` and
`sha256:ffb6cfdab95577f633aa2972c7176cb41f19c2ed21c43ea4dfa232c30a8bbabd` for
the tuple and sequence respectively.

The v0.7.0 release combined that older sequence with a newer environment record.
That combination does not establish a fresh live-worker qualification. This
release preserves the original observation dates and versions. Fresh candidate
checks and packed OCI canaries validate the new artifact separately; they do not
qualify a newer Codex harness or extend the historical window.
